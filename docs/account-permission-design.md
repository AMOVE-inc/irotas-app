# IROTAS アカウント・権限設計書

## 1. 目的

IROTASアプリにおけるアカウント権限を、以下の4つの観点で定義する。

1. 管理者
2. 一般会員
3. 会員ランク（レギュラー／シルバー／ゴールド／プラチナ）
4. 部長

権限は排他的ではなく、一般会員または管理者が会員ランクを持ち、さらに部長を兼任できる。

```text
ログインユーザー
├─ 基本権限: 一般会員 または 管理者
├─ 会員ランク: レギュラー／シルバー／ゴールド／プラチナ
└─ 部活動権限: 一般部員 または 部長（部活ごとに設定）
```

## 2. 権限の優先順位

| 優先度 | 権限 | 説明 |
|---:|---|---|
| 1 | 管理者 | アプリ全体の運営権限。部長権限を含む操作が可能 |
| 2 | 部長 | 任命された部活内に限定した管理権限 |
| 3 | 会員ランク | 特典・料金・限定チャットなどの利用範囲を決定 |
| 4 | 一般会員 | コミュニティの標準利用権限 |

管理者であっても会員ランクは別に保持する。管理者権限だけで上位ランク特典を自動付与するかどうかは、運用ポリシーとして別途決定する。

| 機能 | 一般会員 | 部長 | 管理者 | ランクの影響 |

凡例：○ 利用可能、× 利用不可、条件付き 状態や所属によって利用可能。

運営メンバーと管理者は、DM・部活・ランク・イベントを含む全チャットを閲覧できます。非参加のDM・部活チャットは閲覧のみで、投稿やメンバー操作には参加権限が必要です。部長の閲覧範囲は担当部活・本人の参加状態に従います。

フリーチャットのグループメンションは、`@全体`・`@everyone`・`@チャット内の人全員`がそのチャットの対象会員、`@支部全員`が該当支部チャットの会員、`@関東支部`・`@関西支部`が該当支部の会員を対象とします。部活チャットでは承認済み部員だけに通知し、非参加の運営・管理者や退出済み会員には送信しません。個人メンションとグループメンションが重なっても同一メッセージの通知は1件です。

## 4. 一般会員

### 4.1 役割

コミュニティを利用する標準アカウント。データベース上のロールは `user` とする。

### 4.2 利用可能な機能

- タイムラインの閲覧、投稿、コメント、いいね、共有
- 全国・関東・関西イベントの閲覧と参加
- グルメ会の作成・管理、所属する部活のイベント作成
- 参加イベント専用チャットの利用
- 掲示板の閲覧、投稿、コメント、参加者募集
- 自分が作成した掲示板投稿の編集
- メンバー一覧とプロフィールの閲覧
- ダイレクトチャット、参加中チャットの利用
- 部活動への入部申請と、入部後の活動参加
- グルメマップ、コンシェルジュ、ラジオの利用
- プロフィール、通知、アプリ設定の変更
- 自分のポイント、ランク、クーポンの確認

### 4.3 利用できない機能

- 管理者画面へのアクセス
- 公式イベント、部活、掲示板カテゴリの新規作成
- 他会員の権限・ランク・ポイント変更
- 支払い、承認メール、キャンペーン、分析データの管理
- 部長に任命されていない部活の申請・部員管理

## 5. 管理者

### 5.1 役割

IROTAS全体を管理する運営アカウント。データベース上のロールは `admin` とする。

### 5.2 一般会員に追加される権限

- 管理者ダッシュボードの閲覧
- 会員への管理者権限付与・解除
- 会員の期生、ポイント、ランクの調整
- イロタスポイントの付与と履歴確認
- 会費免除の設定・解除
- イベントの作成・管理、ランク別料金設定
- 支払い状況の確認・変更
- 登録を許可するメールアドレスの追加・削除
- お知らせの作成・削除
- 会員・イベント・ランク・性別などの分析
- キャンペーン管理、CSV取込
- 掲示板カテゴリの追加
- 部活動の作成
- 部長の任命・変更
- 全部活の入部申請・部員管理

### 5.3 管理者専用画面

| 画面 | ルート | 主な用途 |
|---|---|---|
| 管理者ダッシュボード | `/admin-dashboard` | 会員、ポイント、支払い、承認メール、お知らせ、分析 |
| イベント作成 | `/create-event` | イベントとランク別料金の登録 |
| キャンペーン管理 | `/campaign-manager` | プレゼント・キャンペーン管理 |
| CSV取り込み | `/csv-import` | 会員・店舗等の一括登録 |

### 5.4 セキュリティ要件

- 画面上でボタンを隠すだけでなく、画面遷移時にも `admin` を検証する
- DBを更新するAPIは必ずサーバー側の `adminProcedure` で再検証する
- 不明なロール値は一般会員として扱い、管理者権限を付与しない
- 自分自身の最後の管理者権限を削除できないようにする
- 権限変更、ポイント変更、支払い変更は監査ログを残す

## 6. 会員ランク

### 6.1 ランク定義

| ランク | 必要ポイント | 利用可能なランクチャット | 特典の考え方 |
|---|---:|---|---|
| レギュラー | 0XP以上 | なし（レギュラー専用ルームは未設置） | 基本特典 |
| シルバー | 1,500XP以上 | シルバー | シルバー以上のクーポン・割引 |
| ゴールド | 5,500XP以上 | シルバー、ゴールド | ゴールド以上のクーポン・割引 |
| プラチナ | 12,000XP以上 | シルバー、ゴールド、プラチナ | 最上位クーポン・特別料金 |

### 6.2 ランク判定

```text
0〜1,499XP       → レギュラー
1,500〜5,499XP   → シルバー
5,500〜11,999XP  → ゴールド
12,000XP以上     → プラチナ
```

### 6.3 ランクに連動する機能

- イベント参加料金
- 会員限定クーポン
- ランク別チャットルーム
- マイページのランク表示と進捗
- 特典・表彰制度

上位ランクは、自分のランク以下を対象としたコンテンツを利用できる累積方式とする。

### 6.4 ポイント加算ルール

| 行動 | 加算ポイント |
|---|---:|
| イベント参加 | 10pt |
| 掲示板投稿 | 5pt |
| コメント投稿 | 2pt |
| 部活動参加 | 3pt |
| 店舗登録 | 8pt |
| イベント幹事 | 15pt |

## 7. 部長

### 7.1 役割

管理者から部活単位で任命される運営補助ロール。アプリ全体の管理者権限は持たない。

### 7.2 一般部員に追加される権限

- 担当部活の入部申請一覧閲覧
- 入部申請の承認、保留、却下
- 担当部活からの部員退会処理
- 部活動イベントの企画・編集
- 担当部活の投稿・活動情報の管理
- 担当部活のチャット管理

### 7.3 利用できない機能

- 他部活の申請・部員管理
- 新しい部活の作成
- 他会員の部長任命
- 会員ランク、ポイント、支払い、管理者権限の変更
- 管理者ダッシュボードへのアクセス

### 7.4 判定単位

部長権限はユーザー全体の固定ロールではなく、部活ごとの `leaderId` で判定する。

```text
操作対象の部活.leaderId === ログイン会員.id
```

管理者はすべての部活で部長相当の管理操作を行える。

## 8. 複合権限の例

| アカウント例 | 実効権限 |
|---|---|
| 一般会員・レギュラー・部員 | 標準機能＋レギュラー特典 |
| 一般会員・ゴールド・部長 | 標準機能＋ゴールド特典＋担当部活管理 |
| 管理者・シルバー | 全体管理＋シルバー特典 |
| 管理者・プラチナ・部長 | 全体管理＋全ランク特典。部長権限は管理者権限に包含 |

## 9. 現在の実装状況と本番化要件

### 実装済み

- `user` / `admin` の基本ロール
- 管理者専用画面のルートガード
- 管理者専用APIのサーバー側検証
- レギュラー／シルバー／ゴールド／プラチナのランク判定
- ランク別イベント料金、クーポン、チャット
- 部長・管理者による入部申請と部員管理

### 本番実装前に必要

- 会員の支部・期生・ランク・ポイントを認証ユーザーDBへ統合
- 部長権限と部活情報のDB永続化
- 現在ローカル保存になっている管理操作を管理APIへ移行
- 全更新APIで本人・部長・管理者をサーバー側判定
- 管理操作の監査ログテーブル追加
- 最後の管理者を削除できない制約
- 権限変更後のセッション・キャッシュ即時更新
- 権限ごとのE2Eテスト追加
