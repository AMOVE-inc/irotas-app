# 公開後監視・本番スモークテスト

公開後の確認を属人化させず、画面表示・基盤接続・認証境界を一度に確認する。監視は読み取り専用で、投稿・申込み・決済・会員情報を変更しない。

## 実行タイミング

- 毎回の本番公開直後
- 通常運用中は1日1回
- 障害対応後とSecrets更新後
- 会員から「ログインできない」「画面が開かない」と連絡があったとき

## 実行方法

リポジトリ直下で次を実行する。

```sh
pnpm smoke:production
```

別環境を確認するときだけ `IROTAS_BASE_URL=https://... pnpm smoke:production` を使う。監視先はHTTPSを必須とし、ローカルだけHTTPを許可する。

## 自動確認する項目

1. ホーム、ログイン、イベント、掲示板、マイページがHTTP 200で表示できる。
2. `/api/platform/health` がHTTP 200で、D1・R2・認証・Square設定・スキーマ番号がすべて正常である。
3. 未ログイン状態の会員・管理APIがHTTP 401で拒否される。
4. 10秒を超える応答はタイムアウトとして失敗にする。

終了コード0は全件成功、1は1件以上の失敗を表す。出力にはパス、HTTP状態、所要時間と安全なヘルス項目だけを含め、Cookie、認証情報、メールアドレス、会員データ、レスポンス本文は保存しない。

## 異常時の判断

- P0: 未ログインAPIが401以外、会員データ露出の疑い、誤決済。公開停止を判断し、即時に管理者へ連絡する。
- P1: 基盤ヘルス異常、主要画面が開かない、ログイン不能。新規公開を止め、直前版への切り戻しを検討する。
- P2: 一部画面の表示崩れや遅延。影響範囲と再現条件を記録し、次の修正版へ載せる。

異常時は[運用・障害報告・問い合わせ対応手順](./incident-support-runbook.md)に従い、発生時刻、対象パス、HTTP状態、影響範囲、直前の変更だけを記録する。個人情報や決済情報をチケット・Notion・チャットへ貼らない。

## 合格条件

- 全チェックが成功している。
- Sites Workerの直近エラーログが0件である。
- 公開バージョン、コミット、実行時刻、成功件数をNotionのテストログへ記録している。
