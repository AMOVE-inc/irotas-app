# 本番最終移行・更新凍結

## 役割

- 最終判断・データ提供: Non
- 移行実行・技術確認: Codex
- 受入確認: 管理者、運営メンバー、一般会員、部長をまとめて実施

## 凍結前チェック

1. 最新のSquare会員CSV、Discord会員・ロール、部活動、掲示板・チャット、過去イベント参加・幹事履歴を確定する。
2. ファイル名へ確定日時を付け、以降の変更窓口をNonへ一本化する。
3. 会員突合レポートの説明できない重複・未紐付けを0件にする。
4. バックアップ復元訓練を合格にする。
5. 移行開始・終了予定、更新停止対象、緊急連絡先を運営へ告知する。

## 更新凍結中

- Discord側のロール、部活動、イベント履歴、掲示板・チャットの更新を停止する。
- Squareの決済自体は停止せず、移行開始時刻以降のWebhookを別途再照合する。
- アプリ管理画面から会員・権限・ポイント・クーポン等の管理更新を停止する。
- 読み取り利用は継続できるが、移行対象データの新規投稿・編集は停止する。

## 最終移行

1. 更新凍結時刻を記録し、D1・R2の復旧点を作る。
2. ドライラン済みのファイルと件数が一致することを確認する。
3. 会員、ロール・バッジ、部活動、履歴、掲示板・チャット・画像の順に移行する。
4. 各処理の実行ID、取込、更新、除外、エラー件数を記録する。
5. 会員突合レポートと元データの件数を照合する。
6. 凍結時刻以降のSquare更新を再同期する。
7. まとめ受入確認を行い、Go / NoGoを判定する。

## ロールバック条件

- 説明できない会員重複・誤紐付けがある。
- 管理者以外に個人情報・決済連携・管理権限が見える。
- 主要テーブルまたは画像の差分が解消できない。
- ログイン、イベント、掲示板、チャットのいずれかが利用不能。

該当時は書き込みを再開せず、作成した復旧点へ戻す。原因・影響範囲・再実施日だけをNotionへ記録し、個人情報は記録しない。
