# 運営・部長限定テスト手順

## 開始前（順番厳守）

1. 管理者が「管理画面 → バックアップ」で準備状況を確認し、`POST /api/admin/backups` で本番D1の暗号化保管用スナップショットをprivate R2へ作成する。
2. 運営メンバーは `operator`、部長は `club_leader`、一般会員テストは `member` であることを確認する。管理者権限は日常テストに使わない。
3. 決済、抽選確定、大量削除、退会は、運営が指定したテスト用会員・テスト用企画だけを対象にする。本番会員や実決済を対象にしない。
4. 不具合報告には必ず「画面」「操作手順」「発生時刻（JST）」「使用アカウント」を記録する。期待結果、実際の結果、画像も可能なら添付する。
5. 運営・部長で基本動作を確認した後、一般会員テストアカウントで閲覧・投稿・編集・削除・管理画面の権限差を確認する。

## 最終Discord移行の必須条件

- DiscordスレッドIDを一意キーとして同一イベントを照合する。
- アプリで編集済みの項目は保護し、自動上書きしない。
- Discordの新規コメント、画像、参加者など追記可能な情報だけ重複なく追加する。
- 先にdry-runを実行し、新規・更新・保持・競合・スキップ件数と対象を確認する。
- 競合は管理者が現在値とDiscord値を比較し、承認または却下するまで適用しない。
- 適用直前と適用後にバックアップを作成し、テーブル件数とSHA-256を照合する。
- アプリ作成イベントはDiscord移行の削除対象にしない。移行は入力されたDiscordスレッドだけを処理し、全件同期削除を行わない。

## 移行APIの確認文字列

- dry-run: `POST /api/admin/event-import/dry-run`
- 適用: `POST /api/admin/event-import/commit`。`N`件なら `confirmation: "APPLY_N_EVENTS"` が必要。
- 競合解決: `POST /api/admin/event-import/conflicts/{競合ID}/resolve`。`confirmation: "RESOLVE_{競合ID}"` と `decision: "approve" | "reject"` が必要。
